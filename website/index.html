A screen and a timeline: that is the whole source format. The compiler does the cursor, the spotlight, the camera, the subtitles, the guides and the locales.

STEP 1

Describe the screen and the timeline

index.html is the UI, anim.config.json is the choreography: clicks, typing, highlights, camera pushes, each with an explicit time. Hand-write it, or record a real flow once and let record --learn draft it for you. Both are reviewable in a pull request. This timeline is real repo content:

STEP 2

Let the CLI check its own work

check replays the timeline in a headless browser and probes every target right before its step (missing, hidden, 0×0, clipped, off-screen), then reports each camera push's framing as facts. A coding agent fixes a badly aimed zoom like any other lint finding. Real output from this repo:

  • Issues as structured data: every probe and camera-framing fact, ready for a bot to act on.

Honest questions, straight answers.

How is this different from Arcade, Supademo, Storylane, Navattic, Scribe or Tango?
Those tools capture pixels, through a browser extension or a recorder, into a GUI project. A capture is a dead end that rots on contact with the sprint: when the UI changes, someone re-records. A Demoforge demo is source: two text files that regenerate, diff pixel-by-pixel in CI, and compile to video, guide, reel, tour and every locale from one timeline. It is also the only one of the bunch your coding agent can drive end to end; the entire review surface is text and JSON. A capture vendor can bolt on a code export, but the pipeline (build keys, frame diffs, agent review, locale compilation) is the product; copying it means becoming a different product. If your team wants zero code and a GUI editor, those tools are honest alternatives. We built this for the teams they can't serve.
Does it need an API key — or any LLM at all?
No. The whole pipeline (check, build, preview, export, record, guide, tour, localize, build-all) runs locally and headless with no key and no secrets, which is why it runs in CI as-is. The only LLM-powered commands are optional conveniences: extract (screenshot → HTML via a vision model) and animate (prompt → timeline). A coding agent skips both and writes the timeline itself; this website's hero reel was made exactly that way.
What does "rebuilt in CI when the UI changes" mean concretely?
Every build records a content-hash build key (sources + referenced media + render settings + tool revision) into a manifest. build-all --changed-only skips any guide × locale whose key is unchanged and whose video still exists, so a CI run costs seconds when nothing moved. --diff keeps the previous step frames, compares them pixel by pixel and marks a guide stale above a threshold (default 2%), writing the diff images next to them. A UI change shows up as a diff report on the pull request, not as a stale video a customer finds first.
Can it drive our real app, not just a mockup?
Yes. record runs the same timeline against a live URL: real navigations, waitFor gates, Playwright storage state for sign-in, and re-injection of the runtime after each navigation. Every target is probed before its step, and a reset hook (--reset-cmd) puts the app back into its starting state between passes, because a timeline that saves data is not idempotent. check --live --url … is the cheap half of that loop: it replays the timeline for real and probes every selector in seconds, so a typo costs seconds instead of a recording. And record --learn (experimental) turns the same recording into a draft anim.config.json, every observed click, keystroke and navigation re-resolved to the stablest selector the page offers, so your first timeline is written for you.
Is the free tier actually usable, or a crippled trial?
It is the whole CLI, and it is what built everything on this page: unlimited local check/build/preview/export/tour/localize, every output type, batch build-all, no watermark, ISC-licensed source. The paid plans exist because hosting embeds with analytics, running PR-preview builds, serving an agent HTTP API and managing locales genuinely need a server; that is all the cloud sells. If you never need those, the free tier is a complete workflow, forever.
What do I need to run it?
Node 20.6+, npm install, and Chromium through Playwright (npx playwright install chromium). ffmpeg is bundled, nothing else to install. Narration uses OpenAI TTS when a key is present, otherwise macOS say, and is optional. The CI workflow in the repo needs no secrets at all.
Who is Demoforge not for?
If you want to record a demo by clicking through your app once and dragging a hotspot in a GUI, a capture tool will make you faster. That is their strength and we say so. Demoforge pays off when demos are engineering artifacts: many outputs, many locales, frequent UI change, and a repo-and-CI workflow you want your agent to own. And the on-ramp is gentler than "learn a JSON format": record --learn (experimental) watches a recording of your flow and writes the draft timeline for you to clean up. If even that is too much, the GUI vendors are a better fit.
