Product demos as code: versioned with your repo, reviewed in the pull request, rebuilt in CI when the UI changes.

Demoforge compiles your product demo from two text files in the repo — a screen and a timeline. When the UI changes, the demo regenerates: no re-recording, no stale video. One source becomes video, guide, reel, tour — in every locale, and your coding agent can write and review it end to end.

A screen and a timeline — that is the whole source format. The compiler does the cursor, the spotlight, the camera, the subtitles, the guides and the locales.

STEP 1

Describe the screen and the timeline

index.html is the UI, anim.config.json is the choreography — clicks, typing, highlights, camera pushes, each with an explicit time. Both are reviewable in a pull request. This timeline is real repo content:

anim.config.json
{ "meta": { "title": "Draft a proposal response" },
  "steps": [
    { "id": "progress", "time": "2.2s",
      "action": "highlight", "target": ".section-count",
      "title": "Check what is left" },
    { "id": "draft", "time": "6.4s", "action": "type",
      "target": "#editor-type-target",
      "value": "We will ensure rigorous compliance…"},
    { "id": "zoom", "time": "9.6s", "action": "camera",
      "target": "#text-editor", "scale": 1.18 } ] }
STEP 2

Let the CLI check its own work

check replays the timeline in a headless browser and probes every target right before its step — missing, hidden, 0×0, clipped, off-screen — then reports each camera push's framing as facts. A coding agent fixes a badly aimed zoom like any other lint finding. Real output from this repo:

terminal
$ npx tsx cli.ts check demo
· step 5 (6.4s type): target is 0x0
  (empty caret); the spotlight uses its
  sized ancestor #text-editor
· step 6 (9.6s camera): scale 1.18 ·
  window 1627x915 · target 100% visible
OK  9 steps · 0 errors · 1 warning · 3 info
STEP 3

Compile every output from the same source

One command records the video with subtitles and chapters and captures the step guide. Same timeline, other commands: a tour site, a looping reel, a French build. The frame on the right is a captured guide step, untouched:

terminal
$ npx tsx cli.ts export . -o demo.mp4 --guide
$ npx tsx cli.ts build . --embed --device desktop
$ npx tsx cli.ts tour
$ npx tsx cli.ts localize . fr
$ npx tsx cli.ts build-all --changed-only --diff
# every command prints what it wrote

Your agent can review the demo, so you don't have to watch it.

Motion is auditable as text and images. The whole review surface — target probes, camera framing, overlay geometry, frame diffs — is JSON and PNGs a coding agent (or a tired human) can read without pressing play.

  • check --jsonIssues as structured data — every probe and camera-framing fact, ready for a bot to act on.
  • check --tracePer-step overlay geometry — cursor point, spotlight box, subtitle chip and camera window in authored px.
  • preview --motionA real playback pass, sampled — mid-travel framing, cursor glide and typing as they actually play.
  • filmstrip --diffThe encode-level check — the MP4 as a labelled strip plus what-moved-when-where facts, so unintended motion has nowhere to hide.

Demo videos

MP4 with .vtt subtitles, chapter markers for every titled step, and optional narration synthesized with macOS say or OpenAI TTS and mixed in at each step's time.

npx tsx cli.ts export -o demo.mp4

Help guide sites

Scribe-style guides as guide.json, .md and .html with numbered, spotlighted step frames and crops. Publishing a guide is copying a folder.

npx tsx cli.ts export --guide

Marketing reels

Silent looping product clips: MP4, WebM, poster and GIF in one export, plus a self-contained embed page that plays when scrolled into view. This page's hero is one.

npx tsx cli.ts build . --embed

Interactive tours

A self-contained tour site: a rail of scenarios and a canvas that plays them step by step, with play/pause and per-step seeking. Nothing is captured or encoded — it weighs what its HTML weighs.

npx tsx cli.ts tour

Localization

The choreography is shared, so a French build is a strings file, not a re-shoot. Number and currency formats localize too — $2.4M becomes 2,4 M$ — because a translated American product reads as one.

npx tsx cli.ts localize . fr

CI rebuilds

A content-hash build key per guide × locale. --changed-only rebuilds only what changed and --diff compares frames pixel by pixel, marking guides stale above the threshold.

npx tsx cli.ts build-all --changed-only --diff

Honest questions, straight answers.

How is this different from Arcade, Supademo, Storylane, Navattic, Scribe or Tango?
Those tools capture pixels — through a browser extension or a recorder — into a GUI project. A capture is a dead end that rots on contact with the sprint: when the UI changes, someone re-records. A Demoforge demo is source: two text files that regenerate, diff pixel-by-pixel in CI, and compile to video, guide, reel, tour and every locale from one timeline. It is also the only one of the bunch your coding agent can drive end to end — the entire review surface is text and JSON. A capture vendor can bolt on a code export, but the pipeline (build keys, frame diffs, agent review, locale compilation) is the product; copying it means becoming a different product. If your team wants zero code and a GUI editor, those tools are honest alternatives — we built this for the teams they can't serve.
Does it need an API key — or any LLM at all?
No. The whole pipeline — check, build, preview, export, record, guide, tour, localize, build-all — runs locally and headless with no key and no secrets, which is why it runs in CI as-is. The only LLM-powered commands are optional conveniences: extract (screenshot → HTML via a vision model) and animate (prompt → timeline). A coding agent skips both and writes the timeline itself — this website's hero reel was made exactly that way.
What does "rebuilt in CI when the UI changes" mean concretely?
Every build records a content-hash build key (sources + referenced media + render settings + tool revision) into a manifest. build-all --changed-only skips any guide × locale whose key is unchanged and whose video still exists, so a CI run costs seconds when nothing moved. --diff keeps the previous step frames, compares them pixel by pixel and marks a guide stale above a threshold (default 2%), writing the diff images next to them. A UI change shows up as a diff report on the pull request — not as a stale video a customer finds first.
Can it drive our real app, not just a mockup?
Yes. record runs the same timeline against a live URL: real navigations, waitFor gates, Playwright storage state for sign-in, and re-injection of the runtime after each navigation. Every target is probed before its step, and a reset hook (--reset-cmd) puts the app back into its starting state between passes, because a timeline that saves data is not idempotent. check --live --url … is the cheap half of that loop — it replays the timeline for real and probes every selector in seconds, so a typo costs seconds instead of a recording.
Is the free tier actually usable, or a crippled trial?
It is the whole CLI, and it is what built everything on this page: unlimited local check/build/preview/export/tour/localize, every output type, batch build-all, no watermark, ISC-licensed source. The paid plans exist because hosting embeds with analytics, running PR-preview builds, serving an agent HTTP API and managing locales genuinely need a server — that is all the cloud sells. If you never need those, the free tier is a complete workflow, forever.
What do I need to run it?
Node 20.6+, npm install, and Chromium through Playwright (npx playwright install chromium). ffmpeg is bundled — nothing else to install. Narration uses OpenAI TTS when a key is present, otherwise macOS say, and is optional. The CI workflow in the repo needs no secrets at all.
Who is Demoforge not for?
If you want to record a demo by clicking through your app once and dragging a hotspot in a GUI, a capture tool will make you faster — that is their strength and we say so. Demoforge pays off when demos are engineering artifacts: many outputs, many locales, frequent UI change, and a repo-and-CI workflow you want your agent to own. Writing a timeline is writing JSON; if that sentence is a dealbreaker, the GUI vendors are a better fit.
