STEP 1

Describe the screen and the timeline

index.html is the UI, anim.config.json is the choreography: clicks, typing, highlights, camera pushes, each with an explicit time. Your agent writes both and iterates on its own findings; you tweak a time or a selector like any other code change. Reviewable in a pull request, draftable from a real flow with record --learn. STEP 2

Let the CLI check its own work

Motion is auditable as text and images. The whole review surface (target probes, camera framing, overlay geometry, frame diffs) is JSON and PNGs a coding agent, or a tired human, can read without pressing play.

  • Build and audit in one command: export, filmstrip and a structured verify.json (per-step timings, issues), exit 1 on any failure. The one an agent runs.
  • Issues as structured data: every probe and camera-framing fact, ready for a bot to act on.
  • Per-step overlay geometry: cursor point, spotlight box, subtitle chip and camera window in authored px.
  • A real playback pass, sampled: mid-travel framing, cursor glide and typing as they actually play.
  • The encode-level check: the MP4 as a labelled strip plus what-moved-when-where facts, so unintended motion has nowhere to hide.

Demo videos

Help guide sites

Scribe-style guides as guide.json, .md and .html with numbered, spotlighted step frames and crops. Publishing a guide is copying a folder.

Marketing reels

Silent looping product clips: MP4, WebM, poster and GIF in one export, plus a self-contained embed page that plays when scrolled into view. One responsive screen ships desktop and phone reels from the same source, at 2× pixel density. This page's hero is one.

Interactive tours

A self-contained tour site: a rail of scenarios and a canvas that plays them step by step, with play/pause and per-step seeking. Desktop and phone variants build from the same responsive mockup. Nothing is captured or encoded; it weighs what its HTML weighs.

Localization

The choreography is shared, so a French build is a strings file, not a re-shoot. Number and currency formats localize too ($2.4M becomes 2,4 M$), because a translated American product reads as one.

CI rebuilds

A content-hash build key per guide × locale. --changed-only rebuilds only what changed and --diff compares frames pixel by pixel, marking guides stale above the threshold.

Honest questions, straight answers.

How is this different from Arcade, Supademo, Storylane, Navattic, Scribe or Tango?
Those tools capture pixels, through a browser extension or a recorder, into a GUI project. A capture is a dead end that rots on contact with the sprint: when the UI changes, someone re-records. A Vistaro demo is source: two text files that regenerate, diff pixel-by-pixel in CI, and compile to video, guide, reel, tour and every locale from one timeline. It is also the only one of the bunch your coding agent can drive end to end; the entire review surface is text and JSON. A capture vendor can bolt on a code export, but the pipeline (build keys, frame diffs, agent review, locale compilation) is the product; copying it means becoming a different product. If your team wants zero code and a GUI editor, those tools are honest alternatives. We built this for the teams they can't serve.
Does it need an API key — or any LLM at all?
No. The whole pipeline (check, build, preview, export, record, guide, tour, localize, build-all) runs locally and headless with no key and no secrets, which is why it runs in CI as-is. The only LLM-powered commands are optional conveniences: extract (screenshot → HTML via a vision model) and animate (prompt → timeline). A coding agent skips both and writes the timeline itself; this website's hero reel was made exactly that way.
What does "rebuilt in CI when the UI changes" mean concretely?
Every build records a content-hash build key (sources + referenced media + render settings + tool revision) into a manifest. build-all --changed-only skips any guide × locale whose key is unchanged and whose video still exists, so a CI run costs seconds when nothing moved. --diff keeps the previous step frames, compares them pixel by pixel and marks a guide stale above a threshold (default 2%), writing the diff images next to them. A UI change shows up as a diff report on the pull request, not as a stale video a customer finds first.
Can it drive our real app, not just a mockup?
Yes. record runs the same timeline against a live URL: real navigations, waitFor gates, Playwright storage state for sign-in, and re-injection of the runtime after each navigation. Every target is probed before its step, and a reset hook (--reset-cmd) puts the app back into its starting state between passes, because a timeline that saves data is not idempotent. check --live --url … is the cheap half of that loop: it replays the timeline for real and probes every selector in seconds, so a typo costs seconds instead of a recording. And record --learn (experimental) turns the same recording into a draft anim.config.json, every observed click, keystroke and navigation re-resolved to the stablest selector the page offers, so your first timeline is written for you.
Is it really free? What's the catch?
No catch. The whole CLI is free and open source: unlimited local check/build/preview/export/tour/localize, every output type, batch build-all, no watermark, ISC-licensed. It built everything on this page. It costs us almost nothing to offer, because it runs on your machine with your agent. If we ever add a paid hosted service, it will be optional, and the CLI stays free.
Can we keep demos of unreleased features private?
Yes, by default. Vistaro runs entirely on your machine or in your own CI, and nothing is sent to us or anyone else. The demo, the screenshots and the video stay wherever you put them.
What do I need to run it?
If an agent drives it: a clone of this repo and the sentence in the hero; the agent handles the rest, starting with npm install and Chromium through Playwright (npx playwright install chromium). Driving it yourself is the same three steps: Node 20.6+, npm install, the Chromium download. ffmpeg is bundled, nothing else to install, no API key. Narration uses OpenAI TTS when a key is present, otherwise macOS say, and is optional. The CI workflow in the repo needs no secrets at all.
Who is Vistaro not for?
If you want to record a demo by clicking through your app once and dragging a hotspot in a GUI, a capture tool will make you faster. That is their strength and we say so. Vistaro pays off when demos are engineering artifacts: many outputs, many locales, frequent UI change, and a repo-and-CI workflow you want your agent to own. And the on-ramp is gentler than "learn a JSON format": record --learn (experimental) watches a recording of your flow and writes the draft timeline for you to clean up. If even that is too much, the GUI vendors are a better fit.
