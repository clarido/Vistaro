Get started

How to go from nothing to a first product demo. The demo itself takes one sentence to your coding agent; this page covers the setup around it and what to ask for next.

  • What you need
  • Install
  • Ask your agent
  • Ask for more
  • Drive it yourself

  1. What you need

    • Node 20.6 or later on macOS or Linux, and about 150 MB for Chromium. Windows is untested.
    • A coding agent: Claude Code, Codex or Antigravity.
    • The project you want to demo, open in that agent. A running app helps but is not required: the agent can work from your code or from screenshots.

    No account, no API key, no credit card. ffmpeg is bundled.

  2. Install

    Vistaro is on npm. Install it in your project: the version is pinned in your package.json, so your agent always runs the same Vistaro, and its manual lands at a known path.

    in your project · recommended
    $ npm install --save-dev vistaro
$ npx playwright install chromium    # one time: the browser Vistaro records with
$ npx vistaro --help

    Or once for the whole machine

    terminal
    $ npm install -g vistaro
$ npx playwright install chromium
$ vistaro --help

    Or try it without installing

    terminal
    $ npx playwright install chromium
$ npx vistaro@latest init-config demo

    Don't skip the Chromium line: recent npm versions and pnpm don't run install scripts, so it is what downloads the browser. If it's missing, Vistaro stops and prints the command to run. If an agent drives it, you can skip this whole step: the prompt below tells it to install.

  3. Ask your agent

    Open your project in your coding agent and paste this. Vistaro's manual (AGENTS.md) is written for agents, so this is all it needs.

    the prompt 
    Install vistaro as a dev dependency (npm install --save-dev vistaro, then npx playwright install chromium), read node_modules/vistaro/AGENTS.md, and create a product demo of my site.

    The agent writes two files, a screen that mirrors your UI and a timeline of steps, then checks them and looks at the frames, fixing whatever is off before it renders. You get a video with subtitles and a step-by-step help guide. Review it like any other change: read the diff, ask for a different wording or timing, and it renders again.

  4. Ask for more

    The same two files make every other format. Follow-ups that work:

    • "Make a French version."A translated screen and strings file, same choreography.
    • "Turn it into a 10-second loop for our homepage."A silent reel: MP4, WebM, GIF and an embeddable page.
    • "Build an interactive tour with three scenarios."A self-contained tour site visitors can pause and step through.
    • "Record it against our staging app at https://staging.example.com."The same timeline, played in your real app.
    • "Our UI changed. Rebuild the demos."Only what changed is rendered again.

  5. Drive it yourself

    Prefer the command line? From your project, with your demo in demo/:

    terminal
    $ npx vistaro init-config demo    # scaffold the timeline
$ npx vistaro check demo          # probe every step's target
$ npx vistaro preview demo        # one labelled frame per step
$ npx vistaro export demo -o demo.mp4 --guide

    Every command prints what it wrote. npx vistaro --help lists them all, and node_modules/vistaro/AGENTS.md is the full manual.

From source

To contribute, or to run the latest unreleased code, clone the repository instead. Inside it, every command is npx tsx cli.ts where the npm package says npx vistaro.

terminal
$ git clone https://github.com/clarido/Vistaro.git vistaro
$ cd vistaro
$ npm install
$ npx playwright install chromium
$ npx tsx cli.ts --help

If something goes wrong

A step's target is missing
The screen and the timeline disagree about an element. check names the step and the selector; ask your agent to fix it.
Chromium is not found
The install skipped the browser download. Run npx playwright install chromium.
Anything else
Open an issue on GitHub with what you ran and what it printed.
