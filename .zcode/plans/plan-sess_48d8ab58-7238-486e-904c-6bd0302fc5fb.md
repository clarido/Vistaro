# The front door — project picker, scenario switcher, demos command

`npx tsx cli.ts studio` with no argument becomes a launch pad; `studio <dir>` keeps working and lands directly in the editor. Three tiers in one build.

## 1. The scanner (the index of everything editable)
A `scanProjects(root)` function in `src/commands/studio.ts` (exported for reuse by the `demos` command):
- **Screens**: every directory containing BOTH `index.html` and `anim.config.json` (verified: exactly 9 real matches, zero false positives from `-out` dirs; excludes `guides/ask-clarido` which has no screen — it stays out of the picker since the editor requires a screen to preview).
- **Locale dirs excluded as projects**: any path with a `locales/` segment (demo/locales/fr is the French *build*, surfaced as a badge, not a row).
- **Scenario timelines**: per screen, `scenarios/*.json` excluding `*.strings.*.json` (the verified naming separation), plus any `config` fields found in `help.catalog.json` guides and `tour.catalog.json` scenarios (both catalogs resolved relative to the repo root, guarded with try/catch).
- **Per project**: title (`meta.title`), kind (reel if `meta.kind === 'reel'`, else guide; tour badge if the dir appears in tour.catalog), locale flags (`strings.*.json` beside the config + `locales/*` dirs), devices (`only`/`mobile`/`desktop` presence), step count, and **lastTouched** = max `history[].timestamp` from the dir's `anim.manifest.json` (verified field), falling back to the config's mtime.
- Skip list: `node_modules`, `.git`, `.zcode`, `test`, `docs`, `saas`, `*­-out`, `website` root, `sample`.

## 2. Multi-project server (the sandboxed routing)
- Boot builds a **registry**: `[{ id, dir, config, title, kind, ... }]`, `id` = stable short slug (dir path + config stem, hashed to 8 chars). When `studio <dir>` is given, that project is registered (even if the scanner missed it) and the editor defaults to it.
- Every stateful route gains `?project=<id>` — timeline GET/PUT, strings GET/PUT, mockup PUT, preview, check, export, artifact — resolved **only** through the registry (an unknown id is a 404; no path ever reaches the filesystem from a request). This preserves today's no-arbitrary-path property exactly.
- `GET /api/projects` → the scanned list (recents-first), minus the currently open one flagged.
- `/` serves the picker page when no `?project=` is present; with one, the editor boots for that project. Editor assets gain `picker.js` + `picker.html`.

## 3. The picker page
Dark, same token family, one screen: a filter input (fuzzy over title/dir/labels), kind-grouped cards (**Guides / Reels / Tour sources**), each card showing title, dir (+config name when a scenario), kind badge, locale chips, device chips, step count, and "Last touched Oct 3" from the manifests; click → `/?project=<id>`. Keyboard: ↑↓ + Enter. Recents-first ordering.

## 4. The in-editor scenario switcher
When the current project's dir has sibling timelines (demo's three stories), a `<select>` beside the locale switcher lists them ("Draft a response ▾ → What's left · Export to Word"); switching reloads the editor for that project id, carrying device/mode along. This kills the `--config` incantation inside the editor the way the picker kills it at the door.

## 5. The `demos` command
`npx tsx cli.ts demos` prints the same index as a terminal table (title, kind, locales, last touched, and the exact `studio` command to open it) — and doubles as the agent-facing discovery path. Registered in cli.ts, docs regenerated.

## Editor changes
`studio.js`: read `?project=` at boot, thread it through `api()` and `reloadPreview()`; scenario switcher population from `/api/projects`; picker is a separate lightweight page so the editor's boot path is untouched. No schema, runtime, or engine changes.

## Tests + gates
- `test/studio.test.ts` additions: `/api/projects` returns the fixture's project with correct title/kind/recency ordering; project-routed timeline GET round-trips; **an unknown `?project` id is a 404 and never touches disk** (the sandbox assertion); scenario switcher data (sibling timelines of a dir grouped). A new fixture with `scenarios/` + strings files proves scanner separation.
- Manual probe: `studio` with no args on this repo shows all 11 timelines grouped, recents-first; click-through opens each kind; `demos` prints the table.
- Gates: tsc, full studio suite, static suite, docs regen + docs:check.

## Risks
- Registry ids must be stable across rescans (hash of dir+config, not array index).
- Scanner performance on big trees: skip-list + max-depth 4 + pair rule keeps it trivial; rescan on each `/api/projects` call is fine at this scale (and picks up newly created scenarios without a server restart — the picker always tells the truth).
- The picker is a new page but reuses the editor's CSS tokens; no new dependencies anywhere.
