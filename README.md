# Screenshot Animator CLI

Produce the demo videos, the step-by-step help articles and the marketing clips for a web app from the command line, and regenerate them whenever the interface changes.

You describe a screen and a timeline in two text files. The CLI drives a headless browser through that timeline, moving a cursor, clicking, typing and zooming, and records the result. Out comes an MP4 with subtitles and chapters, a numbered help guide with an annotated screenshot for every step, and the same in as many languages as you want. No API key is needed for any of it.

## Why not just record your screen

A screen recording is a dead end: when the product changes you re-record it by hand, it exists in one language, and nobody can review a diff of it. Here a demo is two text files that live in your repository.

- **Regenerate instead of re-record.** The UI moved? Run the command again. `build-all --changed-only` rebuilds only what actually changed and flags the guides whose screenshots drifted.
- **One source for the video and the written guide.** The same timeline produces both, so a help article and its video can never disagree.
- **Every language from one choreography.** Translate a strings file; the clicks, the timings and the camera moves are shared.
- **Reviewable and automatable.** The timeline is JSON in a pull request, and the whole pipeline runs headless in continuous integration.
- **Marketing clips built the same way as the docs.** A homepage animation is a timeline in your repository, reviewed in a pull request and regenerated by a command, not a video file someone re-cuts by hand. It usually has its own mockup rather than sharing one with a help guide, because a marketing composition frames the product to make a point and a guide follows the real screens; what they share is the tool, the choreography vocabulary and the localization path.

Written to be driven by an AI agent: you (or your agent) write the screen and the timeline, the CLI does the recording, the guide capture, the localization scaffolding and the batch builds. **Agents: read [AGENTS.md](AGENTS.md), the manual with every file contract.**

## What you get

- **Video**: MP4 (or GIF) with a moving cursor, a spotlight and a click ripple on every interaction, typing, camera pushes, screen transitions, a subtitle bar, `.vtt` subtitles, MP4 chapters per step and optional narration (OpenAI TTS or macOS `say`).
- **Step guide**: `guide.json`, `guide.md` and `guide.html`, with a numbered frame and a crop per step, the video inline, and the measured timings.
- **Languages**: `localize` scaffolds `locales/<code>/` with a `strings.<code>.json`; the choreography is shared, only the text changes.
- **Batch builds**: `help.catalog.json` + `build-all` produce every guide x locale into one output tree with an `index.json`, rebuilding only what changed and flagging guides whose frames drifted.
- **Live pages**: `record` drives a real app, with real navigations, asynchronous waits and a saved login, from the same timeline.
- **Marketing reels**: the same engine with `"kind": "reel"` in the timeline. The guide chrome (spotlight, ripple, subtitle bar) switches off, the clip is silent, and `export` ships an MP4, a WebM, a poster and a GIF. `build --embed` adds a self-contained `embed-<device>.html` that plays when scrolled into view and loops, plus the parent-side snippet that drives it. One responsive mockup renders at both desktop and phone shapes, with per-device overrides in the timeline.

A step in the generated `guide.md` looks like this, cropped to the element the reader has to click:

```markdown
## 2. Open the report builder

![Step 2](assets/step-02.crop.png)

> Click the primary button to begin.
```

## Setup

```bash
npm install
npx playwright install chromium
```

Node >= 20. Optional keys in `.env` or the environment: `OPENAI_API_KEY` (narration; falls back to macOS `say`), `GEMINI_API_KEY` / `ANTHROPIC_API_KEY` (only for the standalone `extract` and `animate` commands).

## Quick start

```bash
npx tsx cli.ts init-config ./demo        # scaffold anim.config.json next to your index.html
npx tsx cli.ts check ./demo              # schema, timing, and every target in a headless browser
npx tsx cli.ts build ./demo              # animated.html: a self-playing page to open in a browser
npx tsx cli.ts preview ./demo            # preview.png: one labelled frame per step
npx tsx cli.ts export ./demo -o demo.mp4 --guide --narration
```

`export` writes `demo.mp4`, `demo.vtt`, chapters, and `./demo/guide/` (`guide.json`, `guide.md`, `guide.html`, `assets/step-NN.png`). The length comes from the timeline. `animated.html` is generated: run `build` again after editing `index.html` to refresh it, and note that `export` records `index.html` directly, so the video always matches what `check` and `preview` saw.

A timeline is a list of timed interactions on CSS selectors:

```json
{
  "meta": { "title": "Create your first report", "cursor": "mac" },
  "steps": [
    { "id": "intro", "time": "0s", "action": "fadeIn", "target": "body", "title": "Overview", "subtitle": "Welcome to the dashboard." },
    { "id": "open",  "time": "2s", "action": "click", "target": ".btn-primary", "title": "Open the report builder", "narration": "Click the primary button." },
    { "id": "zoom",  "time": "4s", "action": "camera", "target": ".btn-primary", "scale": 1.3, "duration": 2 }
  ]
}
```

### With an AI agent

Paste your screenshots into the agent's chat and ask for the demo:

> *"Here are the three screens of our onboarding. Recreate them, write a timeline that walks through signing up, and export the video with a guide, in English and French."*

The agent writes `index.html` and `anim.config.json`, runs `check`, `build` and `preview` (it reads the PNG and fixes the timeline), exports with `--guide`, then `localize`s and exports each language. The workflow and every file format are in [AGENTS.md](AGENTS.md).

### Other languages

```bash
npx tsx cli.ts localize ./demo fr        # ./demo/locales/fr/ + strings.fr.json, pre-filled
# translate strings.fr.json and the visible text of locales/fr/index.html
npx tsx cli.ts export ./demo/locales/fr -o demo-fr.mp4 --guide
```

### A whole help site

```bash
npx tsx cli.ts build-all                 # every guide x locale of help.catalog.json -> help-out/
npx tsx cli.ts build-all --changed-only --diff
npx tsx cli.ts build-all --help          # catalog schema
```

### A live app instead of a mockup

```bash
npx playwright codegen --save-storage auth.json https://app.local/login   # sign in once
npx tsx cli.ts record ./guides/save --url https://app.local/save --storage-state auth.json -o save.mp4 --guide
```

### Standalone, with an LLM API key

```bash
npx tsx cli.ts extract screenshot.png ./demo --provider gemini      # screenshot -> index.html
npx tsx cli.ts animate ./demo "Fade in, then click the primary button" --provider claude
npx tsx cli.ts export ./demo -o demo.mp4
```

## Tech

Node.js + TypeScript through `tsx` (no build step), `commander`, Playwright Chromium, `ffmpeg-static` (libx264 crf 18, VP9 for WebM), `pixelmatch` for the staleness diff. Desktop exports record at 1920x1080, mobile at 390x844; `--width`/`--height` override.

Video resolution equals the CSS viewport exactly. Playwright's screencast paints one CSS pixel per video pixel and ignores `deviceScaleFactor`, so more pixels come from a bigger viewport, not a denser one: `--scale N` multiplies the viewport and shrinks the layout box back with `:root { zoom: N }`, giving a phone-shaped 780x1688 clip whose layout is still 390x844. Guide screenshots are unaffected and stay at 2x.

Contributing: `npm test` runs the suite (serial, with browser tests; `SKIP_BROWSER=1` to skip them); `npm run docs` regenerates the CLI reference below from `cli.ts`, and `npm run docs:check` fails when it is stale.
